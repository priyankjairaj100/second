Read-only admission
research_v88/storage.py requires explicit project and temporary allowances.
It rejects missing scopes, relative/symbolic paths, unknown quotas, ambiguous
mounts, changed roots, unsupported project-quota mounts and insufficient space.
It sums requirements when both paths share a device. It checks both bytes and
inodes against filesystem availability and the minimum positive user soft/hard
limit. Soft-limit grace is never admission. The project still requires a known
finite user hard limit. A missing quota row never means unlimited space.

For group-quota mounts, the guard queries the group that would own new files:
the existing parent's group when setgid is set, otherwise the effective group.
It sums each group's requirements on a shared device. An explicit all-zero group
limit is interpreted as unlimited for that group only. User and filesystem limits
still apply. Unknown, conflicting or insufficient group evidence refuses.
The future registry must identify the actual write roots and preserve their group
inheritance. This is not an attestation about unrelated files or other write groups.

Only the temporary scope can use explicit XFS noquota mount evidence. Linux's
XFS documentation states that this option disables quota accounting and
enforcement. Other quota flags or a contradictory quota row refuse that path.
Filesystem bytes/inodes must still fit. Source checked23October2026:
https://www.kernel.org/doc/html/latest/admin-guide/xfs.html#mount-options
No mount, quota, directory, environment or file location is changed by the guard.
