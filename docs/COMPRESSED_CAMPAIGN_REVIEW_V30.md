# Compressed pilot registration review

Reviewed the unregistered preparation script, launcher, and two-trial draft.
No registration, empirical conversion, model inference, or quantization was
performed by this review. The resource audit reads an already verified
original model to obtain its 24 stage dimensions.

## Corrected admission failure

The first draft inherited the point solver's 512 MiB array allowance for sparse
certificates. That policy admitted only 12 of 24 stages. It would have forced
every MLP stage to replay before numerical certification was attempted.

| Stage type, repeated six times | Sparse array allowance |
|---|---:|
| QKV | 484,377,088 bytes |
| Attention output | 180,027,904 bytes |
| MLP up | 636,551,680 bytes |
| MLP down | 690,815,488 bytes |

The revised ordered service and worker expose an independent certificate
workspace cap. The draft sets that cap and the sparse budget's workspace to
1 GiB. The matched point policy remains 512 MiB, with its original work and
refinement limits unchanged. Conversion and repair bind the same certificate
workspace. Scalar requests cannot silently adopt an independent larger cap.

All 24 stages now pass structural certificate and fallback admission:

| Quantity | Audited value | Registered cap |
|---|---:|---:|
| Cumulative sparse reservations | 69,956,345,856 | 96,000,000,000 |
| Largest sparse stage reservation | 3,980,275,712 | 6,000,000,000 |
| Largest sparse array allowance | 690,815,488 bytes | 1,073,741,824 bytes |
| Cumulative point fallback work | 21,233,418,240 | 96,000,000,000 |
| Largest point array allowance | 205,529,088 bytes | 536,870,912 bytes |

These are structural proxies and engineering array allowances. They establish
neither certificate acceptance nor whole-process memory fit or elapsed speed.
The six-GiB process ceiling and registered CPU/wall abort limits still apply.
The launcher repeats the complete shape audit before it freezes any campaign.
A known stage refusal now blocks registration.

The detailed audit is
`campaigns/compressed_service_v30_admission_review.json`, bound to the current
draft digest. Only existing original-model evidence is needed for this audit;
it does not satisfy pending cold or quality prerequisites.

## Evidence and gates

The draft now requires verified ordered original, retained lossless, and all
three registered optimized retained cold completions. Every cold model must
match the retained lossless model in hash and byte count. Cold-001 remains the
code oracle. The retained lossless state is explicitly available as the
complete-storage comparator.

The quality prerequisite requires all three Boolean gates:
`development_safety_gate_pass`, `matched_quality_gate_pass`, and
`historical_control_parity_pass`. It additionally binds
`provenance.new_model_sha256` to the actual retained model digest. A completed
quality worker alone is insufficient.

External evidence retains artifact sizes, while resolved worker inputs contain
exactly path and SHA256. Registration checks the complete prospective input
set, including delayed inputs. Delayed bindings cannot replace existing or
external inputs. Conversion and retained repair keep distinct access sets.

The scientific gate requires a strictly smaller complete state and lower
recorded controller latency than the **fastest** of cold-001, cold-002, and
cold-003. It is computed from verified artifact sizes and bound original/current
transaction clocks. The minimum of the three observed times is a conservative
pilot promotion threshold, not a confidence interval or evidence of replicated
repair superiority. Every reference time and transaction digest remain in the
gate report; a tie with the fastest comparator fails the strict gate.

| Registered optimized cold run | Controller seconds |
|---|---:|
| cold-001 | 156.311931796 |
| cold-002 | 140.953662757 |
| cold-003 | 140.549491491 |

The resulting prospective threshold is **140.549491491 seconds**. These are
verified archived observations; no compressed timing was generated by this
review.

`scientific-gates.json` records its result. Later reads recompute the gate and
reject a stale or forged sidecar. A failed scientific gate preserves a valid
completed numerical result and reports `all_passed: false`; it does not erase
the result or authorize repetitions. Exact-output mismatches remain errors.

Both conversion and repair preserve all earlier preparation costs. Current
evidence verification stays inside the declared transaction clocks. Selecting
sparse certification is a prospective hypothesis informed by the earlier
point-backend screen, not evidence that sparse certificates beat primal ones.
