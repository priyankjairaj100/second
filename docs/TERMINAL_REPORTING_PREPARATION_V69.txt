V67 terminal reporting preparation,16 October2026

validation/check_v67_terminal_metadata.py is new read-only reporting code. It is
outside all frozen experiment inventories, imports no numerical implementation,
and cannot submit a job, acquire data or change a ledger. The original V67
workers and both registered cluster auditors remain unchanged.

Use the module entry point with a newly collected metadata archive and a new
output path after reconciling Slurm:
  python3 -B -m validation.check_v67_terminal_metadata ARCHIVE --output NEW_REPORT.json
The output is exclusive; never overwrite an earlier report. A partial snapshot
returns pending_terminal, a failed scheduler row remains terminal_failure_preserved,
and terminal allocations with missing audit/entry receipts remain incomplete.
Terminal-looking JSON cannot override live, failed or missing scheduler evidence.
No comparison table is produced in those cases.

For a complete snapshot, the checker reconciles all twelve worker identities,
commands, plans, applied OS/thread-limit acknowledgements, sealed artifacts,
observed CPU and rounded debits against the final and chronological prefix ledgers.
It verifies the exact audit input inventories, both actual-byte audit claims,
the ten arm/endpoint model-state comparisons, retained/fresh traversal assertions,
modern restoration assertions, original/retained state-plus-trust sizes and
checkpoint-inclusive arithmetic. Copied metadata is rehashed; omitted numerical
and corpus bytes are not locally revalidated. Audit claims are evidence from the
registered cluster auditors, not an independent numerical implementation proof.

Cost fields are recomputed from the saved worker/transaction receipts. Shared
preparation is attributed once per representation; nested request, worker,
transaction and entry clocks stay separate. Audit/qualification/controller CPU
remain outside the numerical ledger. Slurm allocation CPU is reported separately
and batch rows are not added a second time. Missing/duplicate accounting rows or
wall-cap overshoots are rejected. Five comparison arms share four stored
representations: cached and cold both use lossless. Earlier handoff wording that
said five stored representations was incorrect and is corrected at this checkpoint.
